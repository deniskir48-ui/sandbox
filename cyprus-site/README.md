# Сайт-гид по Кипру — MVP

Статический сайт на [Astro](https://astro.build): Гид (компании), Афиша (мероприятия), Статьи, О проекте, Поиск.
Без backend и базы данных: контент хранится в файлах YAML/Markdown в репозитории.

Название сайта и домен ещё не выбраны. Временное название задаётся в `src/config.ts`.

## Быстрый старт

Нужен Node.js 18.20+ (проверено на 22).

```bash
cd cyprus-site
npm install
npm run dev              # http://localhost:4321 — боевые данные (сейчас 0 опубликованных записей)
npm run dev:fixtures     # то же на тестовых фикстурах: видно, как выглядят заполненные страницы
npm run build            # проверка данных + сборка в dist/
npm run preview          # просмотр собранной версии
```

| Команда | Что делает |
|---|---|
| `npm run check:data` | Проверка данных: email в публичных полях, ссылки статей на неопубликованные компании, даты проверки |
| `npm run build:fixtures` | Сборка с фикстурами в `dist-fixtures/` (с плашкой «Тестовый режим» и noindex) |
| `npm run dev:preview`, `npm run build:preview` | Предпросмотр: все черновики видны с пометкой «Данные не проверены» (только для закрытого просмотра, noindex) |
| `npm run import:catalog -- <файл.csv>` | Импорт внутренней базы в черновики (см. ниже) |

## Структура

```
src/
  config.ts               название сайта, меню
  data/taxonomy.ts        8 разделов Гида, подкатегории, типы мероприятий
  content.config.ts       схемы данных и правило публикации
  content/
    companies/*.yaml      компании (197 черновиков из внутренней базы)
    events/*.yaml         мероприятия
    articles/*.md         статьи
  pages/                  страницы и адреса (см. таблицу ниже)
  lib/                    выборки данных, даты (часовой пояс Кипра), фильтры
fixtures/                 технические тестовые данные; продакшен их не видит
scripts/                  импорт CSV и проверка данных
docs/templates/           шаблоны компании, события, статьи
docs/research/            инвентаризация данных и план от 11.11
```

| Адрес | Страница |
|---|---|
| `/` | Главная: поиск, разделы Гида, ближайшие события, статьи |
| `/catalog/`, `/catalog/<раздел>/` | Гид и раздел (фильтры по подкатегории и городу) |
| `/services/<slug>/` | Карточка компании |
| `/events/`, `/events/<slug>/` | Афиша (фильтры: когда, город, тип) и страница события |
| `/guides/`, `/guides/<slug>/` | Статьи |
| `/about/`, `/search/?q=` | О проекте, поиск |

## Как добавлять данные

### Правило публикации

У каждой записи есть `status: draft | published`. На сайте видны **только** `published`.
Сборка **упадёт**, если у опубликованной записи нет обязательных полей:

- компания: `summary`, `sources`, `verified_at`;
- событие: `summary`, `ticket_url`, `sources`, `verified_at`.

Поля без проверенных данных просто не заполняйте: на странице они не показываются.

### Компания

1. Найдите черновик в `src/content/companies/` (имя файла = адрес `/services/<имя>/`) или скопируйте `docs/templates/company.yaml`.
2. Проверьте данные по официальному источнику. Заполните `summary`, `description`, `website` или `channel`, `sources`, `verified_at`. Неподтверждённый город удалите.
3. Поставьте `status: published` и запустите `npm run build`.

Филиалы сети — отдельные файлы с общим полем `network` (пример: три кампуса PASCAL).

### Мероприятие

Скопируйте `docs/templates/event.yaml` в `src/content/events/<название>-<город>-<дата>.yaml`.
Прошедшие события автоматически скрываются из Афиши, поиска и главной: при сборке и в браузере по дате Кипра.
Их страницы остаются с пометкой «Мероприятие прошло» и `noindex`. Старые файлы можно удалять.

### Статья

Скопируйте `docs/templates/article.md` в `src/content/articles/<slug>.md`.
Компании из Гида: список `companies: [slug, ...]` (блок внизу статьи) и обычные ссылки `/services/<slug>/` в тексте.
`check:data` не даст опубликовать ссылку на неопубликованную компанию.

### Импорт из внутренней базы (Google Sheets)

1. Таблица «Кипр — единый каталог…» → Файл → Скачать → CSV.
2. Положите файл в `cyprus-site/import/` (папка в `.gitignore`, в git не попадает).
3. `npm run import:catalog -- import/catalog.csv`

Импорт берёт **только** публичные колонки: название, категория, город, сайт, публичный канал, сеть.
Email, телефоны, статусы переписки и заметки отбрасываются. Создаются только черновики.
Повторный запуск безопасен: записи узнаются по `source_id`, существующие файлы не перезаписываются.
Флаг `--refresh-drafts` обновляет поля из таблицы в файлах, которые ещё в статусе `draft` (опубликованные не трогает).

### Импорт недельной афиши (Google Sheets)

Таблица вида «Афиша Кипра · 9–15 ноября 2026» → Файл → Скачать → .xlsx (именно xlsx: в CSV пропадают ссылки из формул `HYPERLINK`).

```bash
pip install openpyxl
python3 scripts/import-afisha.py import/afisha.xlsx
```

Создаются черновики в `src/content/events/`. Строки с пометками «объединить», «уже есть общ…», «НЕ включать» пропускаются.
Тип события определяется по ключевым словам; проверьте его в файле. Замечания редактора остаются комментарием в файле и на сайт не попадают.

## Форма «Добавить компанию»

Страница `/add-company/`. Подключение приёма заявок в Google-таблицу описано в `docs/forms/README.md` (переменная `PUBLIC_FORM_ENDPOINT`).

## Деплой (когда будет выбран домен)

Рекомендуется Cloudflare Pages или Netlify (бесплатный тариф):

- Root directory: `cyprus-site`, build command: `npm run build`, output: `dist`.
- Переменная окружения `SITE_URL=https://<домен>`. Без неё сайт собирается с `robots.txt: Disallow: /` и без sitemap, так задумано для черновика.
- Для Афиши настроить ежедневную пересборку (deploy hook + cron), чтобы прошедшие события уходили и из HTML. В браузере они скрываются и без этого.

## Расширение без переделки

- CMS: структура «один файл = одна запись» подходит для Git-based CMS (Decap/Sveltia/TinaCMS) поверх тех же файлов.
- Google Sheets: можно добавить скрипт выгрузки таблицы → YAML с тем же правилом публикации.
- Новые поля карточки — в схеме `src/content.config.ts` и шаблоне `src/pages/services/[slug].astro`.
